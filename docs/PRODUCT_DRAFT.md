# Slideform — 제품·개발 초안

## 1. 제품 정의

**한 장으로 합쳐진 AI 슬라이드 이미지를 읽고, 시각 요소를 분리하고, 사람이 검수한 뒤 편집 가능한 PowerPoint로 재구성하는 도구.**

주 사용자는 AI 이미지·슬라이드 생성 도구로 발표 자료를 만든 기획자, 마케터, 디자이너입니다. 글자 하나를 수정하기 위해 슬라이드 전체를 다시 생성하는 부담을 줄이는 것이 목표입니다.

‘원본과 같은 모습’과 ‘개별 요소를 자유롭게 편집’은 서로 다른 품질 기준입니다. 변환 결과를 하나의 성공률로 감추지 않고 **텍스트 정확도, 위치 정확도, 배경 복원, 편집 가능 범위**로 나눠 보여줍니다. 불확실한 글자를 임의로 완성하지 않습니다.

## 2. 사용 흐름

1. **불러오기:** 여러 이미지 또는 PDF를 업로드합니다. 페이지별 슬라이드를 만들고 순서와 비율을 확인합니다.
2. **분석:** PaddleOCR로 텍스트와 레이아웃을 인식합니다. 이미지·표·차트의 영역도 찾습니다.
3. **분리:** 원래 좌표, OCR 폴리곤, 잘라낸 이미지, 제거 마스크, 편집용 요소를 별도로 관리합니다.
4. **검수:** 원본과 복원 결과를 비교합니다. 낮은 신뢰도, 작은 글씨, 배경 손상, 겹친 요소부터 확인합니다.
5. **편집:** 텍스트, 위치, 크기, 글꼴, 줄바꿈, 이미지 경계를 수정합니다.
6. **내보내기:** 편집형 PPTX 또는 원본 이미지 PPTX를 선택합니다. 미검수 항목과 이미지로 유지되는 요소를 미리 보여줍니다.

현재 초안의 흐름은 ‘이미지/PDF → 수동 분리 또는 OCR 연결 → 편집/검수 → PPTX’까지입니다. 대량 작업 큐, 인페인팅, 자유형 객체 분리는 아래 개발 단계에서 추가합니다.

## 3. 편집 화면

| 구역 | 구성 | 세심하게 다룰 부분 |
|---|---|---|
| 상단 | 프로젝트 이름, 저장, 내보내기 | 저장 여부를 사실대로 표시; 새로고침 시 미저장 작업 안내 |
| 왼쪽 | 페이지 썸네일, 분석 상태, 영역 수, 순서 | 현재 페이지와 검수 필요 페이지 구분 |
| 중앙 상단 | 분석, 원본/분리 결과, 실행 취소 | 재분석은 기존 수정을 대체하므로 명시적으로 선택 |
| 중앙 캔버스 | 텍스트·이미지 경계, 선택, 이동, 크기 조절 | 원본 비율 유지; 좌표 기준 통일; 줌과 실제 크기 구분 |
| 도구 | 선택, 텍스트 영역, 이미지 영역 | 누락된 인식 결과를 수동으로 보완 |
| 오른쪽 | 요소 목록, 문구, 스타일, 위치, 검수 | 요소 숨김·잠금·삭제, 저신뢰도 안내, 원문과 대응 |
| 하단 | 작업 상태와 요소 수 | OCR 미연결을 성공처럼 표시하지 않음 |

텍스트 영역과 이미지 영역에 서로 다른 경계색을 사용합니다. 마우스 외에 좌표 입력과 키보드 이동을 제공합니다. 모바일은 슬라이드 목록을 가로로 배치하고 속성 패널을 아래에 둡니다. 정밀 편집의 주 사용 환경은 데스크톱입니다.

## 4. 정교한 분리 파이프라인

### 4.1 입력과 좌표

- 원본 파일과 분석용 래스터를 구분합니다. 원본 해시, 변환 배율, 페이지 번호를 보존하는 구조로 확장합니다.
- 가로·세로가 다른 슬라이드를 억지로 늘리지 않습니다. PPTX는 문서 전체가 같은 페이지 크기를 쓰므로 다른 비율은 여백 또는 명시적 크롭으로 처리합니다.
- 현재는 이미지 1개 = 슬라이드 1개, PDF 1페이지 = 슬라이드 1개입니다. 여러 슬라이드가 한 이미지에 붙어 있는 경우의 자동 분할은 별도 기능입니다.
- 회전·왜곡 보정을 도입할 때는 반드시 원본으로 되돌리는 변환 행렬을 저장합니다. 현재는 해당 보정을 꺼서 좌표 오차를 막습니다.

### 4.2 레이아웃·텍스트 인식

PaddleOCR의 **PP-StructureV3**를 레이아웃 분석에 사용하고 한국어·영어 자료에는 해당 언어의 PP-OCRv5 인식 모델을 연결하는 방향입니다. 엔진과 모델은 버전을 고정하고 실제 자료로 호환성을 검증한 뒤 서비스에 반영합니다.

보존해야 할 정보: 원문, 폴리곤, 회전 각도, 인식 신뢰도, 레이아웃 종류, 읽기 순서, 엔진 버전. 신뢰도를 알 수 없으면 ‘알 수 없음’으로 기록합니다. 높아 보이는 수치를 채워 넣지 않습니다.

현재 어댑터는 행 단위 OCR을 텍스트 요소로 만들며, 문단 자동 병합은 구현 전입니다. 문단 병합 시에는 행간·들여쓰기·폰트 높이·읽기 순서를 함께 비교하고 사용자에게 분할/병합 도구를 제공해야 합니다.

AI 이미지에는 실제 문자가 아닌 유사 글리프가 있을 수 있습니다. OCR 또는 언어 모델이 그럴듯한 문장으로 바꿨다는 이유만으로 ‘복원 완료’ 처리하지 않습니다. 원문과 추천 교정안을 함께 보여주고 사용자가 확정합니다.

### 4.3 이미지·도형·차트

- **현재:** 사각형 이미지 영역을 잘라내 독립 이미지로 저장합니다. 표·차트도 이미지로 유지합니다.
- **다음 단계:** 자유형 마스크와 객체 분할 모델로 배경을 분리하고 투명 PNG를 생성합니다. 자동 마스크는 브러시로 수정할 수 있어야 합니다.
- 이미지 안의 글자는 기본적으로 이미지에 유지합니다. 같은 글자를 별도 텍스트로 겹쳐 만드는 중복을 막습니다.
- 표·차트를 네이티브 객체로 바꾸는 기능은 셀 구조·축·범례·데이터 값의 별도 검증을 통과한 경우에만 제공합니다. 픽셀만 보고 원본 수치를 확정하지 않습니다.
- 겹친 객체의 가려진 부분은 원본에 정보가 없습니다. 복원된 부분을 명시하고, 원본 전체를 이미지로 유지하는 선택지도 제공합니다.

### 4.4 텍스트 제거와 배경 복원

PaddleOCR는 읽기와 위치 인식의 구성 요소입니다. **글자를 지운 배경 생성과 객체의 투명 분리는 별도의 처리**입니다.

현재 초안은 추출된 원래 사각형 영역을 주변 색상의 중앙값으로 채웁니다. 단색 배경의 레이아웃 검증에는 유용하지만 사진, 그라데이션, 질감, 그림자에는 손상이 남을 수 있습니다. 이 제한은 화면과 내보내기 창에 표시합니다.

정식 구현은 아래 순서로 진행합니다.

1. OCR 사각형을 그대로 지우지 않고 실제 글자 픽셀의 마스크를 정제합니다.
2. 작은 마스크 확장을 적용해 안티앨리어싱 잔상을 줄입니다. 확장 폭은 원본 해상도에 비례시킵니다.
3. 다른 객체의 보호 마스크를 빼서 글자 주변 그림이나 선을 지우지 않도록 합니다.
4. 단색·단순 그라데이션은 추정 복원, 복잡한 배경은 인페인팅으로 분기합니다. LaMa 계열 등의 후보를 실제 슬라이드로 비교합니다.
5. 제거 전/후, 마스크, 복원 결과를 비교하고 부분 되돌리기를 제공합니다.
6. 복원 품질이 낮으면 원본 보존 선택을 제안합니다. 시각적 유사도 하나만으로 승인하지 않습니다.

### 4.5 글꼴과 재배치

- 글자 높이를 폰트 크기로 추정하되, 원래 글꼴을 정확히 알았다고 표시하지 않습니다.
- 자간, 행간, 굵기, 정렬, 회전을 각각 조절할 수 있게 확장합니다.
- 한글 대체 글꼴을 프로젝트 단위로 지정하고 실제 설치 가능성과 배포 권한을 확인합니다.
- 자동 맞춤으로 중요한 문구가 잘리거나 지나치게 작아지지 않게 최소 글꼴 크기와 넘침 검사를 둡니다.
- PPTX에서 사용할 글꼴로 렌더링한 이미지와 브라우저 캔버스를 비교합니다. 글꼴 임베딩은 별도 지원·라이선스 검토 대상입니다.

## 5. 데이터와 API

현재 구현의 최소 프로젝트 구조입니다.

```text
Project
  version, title
  slides[]
    id, name, width, height, source, demo, analyzed
    layers[]
      id, type, name, box{x,y,w,h}, visible, locked
      reviewed, confidence
      text, fontFamily, fontSize, color, bold, align
      image
    eraseRegions[]
      id, box{x,y,w,h}, color
```

`eraseRegions`는 원본에서 제거할 위치이고 `layer.box`는 편집 후 놓을 위치입니다. 둘을 분리해야 요소를 이동해도 원래 위치의 글자가 다시 나타나지 않습니다. 삭제·숨김도 같은 원칙을 따릅니다.

현재 API:

| API | 역할 | 오류 |
|---|---|---|
| `GET /api/health` | 서버·엔진 설치·모델 로드 상태 | 연결 실패와 미설치 구분 |
| `POST /api/analyze` | 이미지와 언어를 받아 레이어 반환 | 413 크기, 415 파일, 422 언어, 429 사용 중, 503 엔진 |

정식 서비스에서 추가할 구조:

- `Project / Slide / Asset / Layer / Mask / ReviewIssue / ExportJob` 엔티티
- `POST /projects`, `POST /projects/{id}/assets`, `POST /slides/{id}/analysis-jobs`
- `GET /jobs/{id}` 또는 SSE 작업 상태, 취소와 재시도
- `PATCH /slides/{id}/layers`, `POST /layers/{id}/restore-background`
- `POST /projects/{id}/exports`, 완성 파일 다운로드

출처 좌표·모델 결과는 불변으로 보존하고 사용자의 수정은 별도 버전으로 저장합니다. 파일 해시와 분석 설정으로 중복 작업을 줄이고 재시도 시 같은 작업이 여러 번 실행되지 않게 합니다.

## 6. 구현 구성

현재: **React + Vite / Canvas·DOM 편집 / PDF.js / PptxGenJS / FastAPI / PaddleOCR 연결 코드**.

후속 편집 기능이 복잡해지면 전용 캔버스 라이브러리 도입을 검토합니다. 초기부터 복잡한 편집 엔진을 만들기보다 회전·다중 선택·정렬·마스킹이 필요한 시점에 검증합니다.

정식 서버 구성은 API와 GPU 추론 작업자를 분리합니다. 파일은 객체 저장소, 메타데이터는 관계형 DB, 작업 상태는 큐로 관리합니다. 추론 작업자가 브라우저 요청 수명에 묶이지 않아야 대량 문서를 안정적으로 처리할 수 있습니다. 실제 사용량이 정해진 뒤 인프라를 선택합니다.

현재 버전은 로컬 단일 사용자 도구입니다. 클라우드 공개 전에는 프로젝트별 접근 권한, 업로드 검사, 파일 보관·삭제 정책, 요청 한도, 다운로드 권한을 구현해야 합니다. 생성 모델에 보내는 경우에는 외부 전송 범위도 화면에 표시합니다.

## 7. 품질 검수 기준

아래 수치는 출시 목표를 정하기 위한 **초기 제안**이며 달성한 성능이 아닙니다. 실제 데이터 평가 후 조정합니다.

| 항목 | 확인 방식 | 초기 제안 |
|---|---|---|
| 텍스트 정확도 | 한글·영문·혼합·작은 글씨별 CER | 읽을 수 있는 일반 자료에서 CER 2% 이하 목표 |
| 위치 정확도 | 원본 폴리곤과 복원 영역 비교 | 평균 위치 오차 2px@1920px 수준 목표 |
| 영역 누락 | 텍스트/그림/표/차트별 recall | 주요 객체 누락 여부를 반드시 사람 검수 |
| 중복 | 이미지 안 글자와 텍스트 상자 겹침 | 확정 요소에서 중복 글자 0개 |
| 배경 | 경계·잔상·보호 객체 손상 비교 | 검수 승인 없는 복잡한 배경을 자동 완료하지 않음 |
| PPTX 구조 | ZIP/XML에서 텍스트 상자·이미지 확인 | 모든 편집형 텍스트를 실제 텍스트 상자로 출력 |
| 실제 PPTX | PowerPoint/LibreOffice로 렌더 비교 | 내용 누락·넘침·폰트 대체 문제 분리 기록 |
| 복원 가능성 | 저장/재열기/실행 취소 | 모든 수정 사항 재현 |

최소 평가 자료에는 한글·영문 혼합, 세로형 페이지, 낮은 해상도, 투명도·그림자, 회전 글자, 사진 위 글자, 표·차트, 겹친 이미지, AI가 만든 비정상 글리프를 포함합니다. ‘잘 되는 샘플’만 평균 내지 않고 유형별 실패를 보고합니다.

## 8. 개발 우선순위

### 단계 A — 사용 흐름 확인: 현재 초안

입력 → 수동 분리 → 텍스트 편집 → 검수 → PPTX가 끝까지 이어집니다. 실제 사용자가 필요한 조작과 편집 밀도를 확인합니다. 결과물은 현재 저장소의 웹앱입니다.

### 단계 B — 실제 OCR MVP

목표 환경에 PaddleOCR를 설치하고 엔진·모델 버전을 고정합니다. 실제 슬라이드 30~50장으로 정확도와 처리 시간을 측정하고 문단 병합, 누락 영역 추가, 분석 진행률·취소·재시도를 구현합니다. 모델 설치만으로 완료 처리하지 않습니다.

### 단계 C — 시각적 복원

글자 마스크, 배경 인페인팅, 객체 보호, 자유형 이미지 분리, 마스크 수정 브러시를 구현합니다. 회전·다중 선택·정렬·레이어 순서를 추가합니다. 이 단계가 결과물의 정교함을 좌우합니다.

### 단계 D — PPTX 품질·운영

PPTX 렌더링 비교, 넘침 검사, 글꼴 대체 안내, 네이티브 표·차트의 선택적 변환을 추가합니다. 자동 저장, 작업 큐, 사용자 프로젝트 관리, 원본 보관·삭제 정책을 갖춥니다.

## 9. 우선 결정할 사항

초안에서는 **로컬 실행, 한국어+영어, 이미지/PDF 입력, 16:9 중심, 수동 검수, 편집형 PPTX**를 기준으로 잡았습니다. 다음 구현에서 실제 사용자 자료와 함께 확인할 사항은 평균 슬라이드 수, 목표 처리 시간, GPU 환경, 외부 이미지 전송 허용 여부, 편집 가능성 대비 원본 재현의 우선순위입니다.
