# 초안 검증 기록

검증일: 2026-09-19. Windows / Node.js 24 / Python 3.12 / Edge 환경.

## 완료

- Vite 프로덕션 빌드 성공
- JavaScript 테스트 6개 통과: 영역 경계, 종횡비 보존, 순서 변경, 검수 집계, 프로젝트 검증
- Python 테스트 7개 통과: API 상태·입력·미설치 오류, 이미지 좌표 정규화, 차트 문구 중복 제외
- 브라우저에서 샘플 3장 렌더링, 텍스트 수정·잠금·검수 완료 확인
- PNG 불러오기 후 허구의 OCR 요소가 생성되지 않는 상태 확인
- OCR 미설치 시 503 안내 확인
- 영역 드래그로 이미지 분리, 좌표 수정, 실행 취소, PNG 다운로드 확인
- 프로젝트 JSON 저장 후 다시 열어 수정된 문구와 페이지 복원 확인
- 2페이지 PDF를 독립된 두 슬라이드로 불러오기 확인
- 편집형 PPTX 및 원본 이미지 PPTX 다운로드 확인
- 데스크톱 1440×1000, 모바일 390×844 렌더링 확인
- 테스트 중 잡히지 않은 JavaScript 예외 없음

## PPTX 파일 내부 검증

브라우저에서 내려받은 PPTX를 ZIP으로 열어 Open XML을 검사했습니다.

| 파일 | 페이지 | 페이지별 객체 | 추가 확인 |
|---|---:|---|---|
| 편집한 샘플 | 3 | 텍스트 상자 4개, 이미지 2개 | 변경한 한국어 문구가 텍스트 객체에 저장됨 |
| 원본 PDF 페이지 | 2 | 텍스트 상자 0개, 이미지 1개 | 원본 이미지 출력 모드와 일치 |

편집형의 이미지 2개는 복원 배경 1개와 분리된 그래프 이미지 1개입니다. 단순히 전체 슬라이드를 이미지 한 장으로 저장하고 ‘편집 가능’으로 표시하는 구현이 아닙니다.

## 아직 검증하지 않은 항목

- PaddleOCR 엔진 및 모델의 실제 추론: 이 환경에는 모델을 설치하지 않았습니다.
- 실제 사용자 자료에서의 OCR 정확도·모델 처리 시간·메모리 사용량
- 데스크톱 PowerPoint 또는 LibreOffice의 시각적 렌더링, 글꼴 대체와 줄바꿈 차이
- 복잡한 배경 인페인팅과 자유형 객체 분리: 미구현입니다.
- 최대 30장/파일당 30MB 수준의 장시간·메모리 부하 테스트
- 서버 동시 사용자, 인증·접근 제어, 클라우드 배포: 로컬 초안의 범위 밖입니다.
